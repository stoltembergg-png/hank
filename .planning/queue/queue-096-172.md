### PR-096

- **ID:** PR-096
- **Categoria:** FOUNDATION
- **Milestone:** M5 — Tools
- **Título:** Define Tool trait
- **Objetivo:** Definir o contrato mínimo e desacoplado para ferramentas executáveis.
- **Problema resolvido:** Sem um contrato comum, registry, permission engine, runtime e ferramentas concretas não conseguem interoperar nem ser auditados uniformemente.
- **Escopo:** Trait para identidade, descrição, schema, capability, execução, resultado, erro, timeout/cancelamento e ambiente; contexto de projeto, política, orçamento e trace no request.
- **Não-escopo:** Implementar filesystem, terminal, HTTP, Git, Python, UI ou sandbox concreto.
- **Arquivos/crates prováveis:** `crates/tool-core/src/trait.rs`, `crates/tool-core/src/context.rs`, `crates/tool-core/src/error.rs`.
- **Dependências anteriores:** PR-021 IDs tipados, PR-022 erros, PR-023 eventos, PR-047 budget policy, PR-044 tool permission schema.
- **Requisitos funcionais:** Tool request deve transportar `project_id`, agent/session/task identity, capability, policy decision, budget reservation e trace ID; resultado deve distinguir sucesso, negação, timeout, cancelamento e falha; handler não pode obter contexto implícito de outro projeto.
- **NFRs:** Trait async e provider-agnostic; tipos serializáveis onde necessários; limites explícitos de payload/resultado; determinismo em mocks; compatível com sandbox.
- **Critérios de aceite verificáveis:** Compilador aceita uma ferramenta fake conforme o trait; request sem identidade, capability, projeto, orçamento ou trace é rejeitado; erros são tipados e não vazam secrets; nenhum módulo de UI ou provider concreto é dependência.
- **Testes obrigatórios:** Unit tests do contrato, teste de ferramenta fake, integração de erro/timeout/cancelamento, contract test de serialização e teste de isolamento entre dois `project_id`.
- **Verificações de segurança:** Rejeitar contexto incompleto; negar default; impedir handler de chamar shell diretamente; testar que texto de modelo não altera policy/capability.
- **Observabilidade:** Eventos `ToolStarted/Finished` com tool, projeto, identidade, decisão, orçamento, trace, duração e erro; nunca registrar argumentos sensíveis em claro.
- **Documentação:** Documentar trait, lifecycle, erros, invariantes de isolamento e fluxo Permission Engine → Tool Runtime.
- **Definition of Done:** Contrato revisado, testes e docs planejados/implementados quando a PR for executada, sem `unwrap` inseguro, sem TODO oculto, sem escopo alheio e com rollback do contrato versionado.
- **Condição para desbloquear a próxima PR:** O contrato está estável e permite definir schema sem implementar ferramentas.

## Fechamento da fatia

As condições de desbloqueio formam o caminho crítico sem dependências inexistentes: tools foundation → concrete tools/guards → Python protocol/transport/lifecycle → SDK/registration/execution → memory entity/repository/taxonomy → candidate/dedupe/retrieval/context → skill manifest/parser/repository/loader → scopes/bindings/version/UI/test/validation → governed evolution/rollback → group/membership/session → invocation protocol/delegation → graph/cycle/depth → bounded parallel/budget/policies/rounds/synthesis → read-only UI projections. A fila termina em PR-172; nenhuma PR posterior foi criada ou presumida como implementada.
