# RUSTSEC-2024-0429 / GHSA-wrw7-89jp-8q8g

## Status

**OPEN / ACCEPTED UPSTREAM RISK**

This is not resolved. The exception is a narrowly scoped, tracked acceptance of
an upstream transitive dependency risk while the supported Tauri/GTK stack remains
on the affected gtk-rs major line.

## Advisory

- Advisory: `RUSTSEC-2024-0429`
- Alias: `GHSA-wrw7-89jp-8q8g`
- Dependency: `glib 0.18.x` (currently `0.18.5` in the desktop lockfile)
- Patched upstream: `glib >= 0.20.0`
- Classification: `UPSTREAM_TRANSITIVE_DEPENDENCY`
- Mitigation status: `NO_COMPATIBLE_UPSTREAM_FIX_AVAILABLE`

## Hank exposure analysis

- `DIRECT_USAGE`: `NO`
- `REACHABLE_FROM_HANK_CODE`: `UNKNOWN`
- `TRANSITIVE_ONLY`: `YES`

The Hank source tree does not call `VariantStrIter`, `variant_str_iter`, or
`g_variant_get_child`, and does not import `glib` or `glib_sys` directly. The
runtime dependency is nevertheless loaded through the native desktop chain, so
absence of a direct call is not treated as proof of zero runtime exposure.

## Dependency chain

```text
hank-desktop
  -> tauri 2.11.5
  -> tauri-runtime-wry / wry
  -> webkit2gtk 2.0.2
  -> gtk 0.18.2
  -> glib 0.18.5
```

The supported stack currently requires `gtk 0.18.2`, whose dependency constraint
is `glib ^0.18`. A controlled attempt to select `glib 0.20.0` fails dependency
resolution; editing the lockfile or forcing an incompatible patch would be unsafe.

## Rationale and mitigation

- Origin: transitive dependency of the Tauri/GTK Linux desktop stack.
- No compatible upstream fix is available for the currently pinned Tauri/Wry/GTK
  line.
- No manual lockfile edit, incompatible patch, GTK/WebKit breakage, or major stack
  migration is permitted by this exception.
- Tauri/GTK/WebKit upgrades remain monitored by the dedicated Dependabot update
  block for `apps/desktop/src-tauri`.
- Rust audits continue to emit the raw advisory report. The security gate evaluates
  only vulnerabilities/unsound findings whose exact package/version appears in the
  corresponding resolved `cargo tree`; optional lockfile-only findings remain visible
  as `UNREACHABLE_AUDIT_FINDINGS`. Among reachable findings, the gate accepts only
  this exact advisory and fails on any new advisory or audit execution error.

## Security decision

This exception does not suppress the advisory from `cargo audit`, does not mark it
resolved, and does not authorize broad vulnerability ignores. It distinguishes the
known upstream risk from new actionable regressions while preserving fail-closed
behavior for every other advisory.
